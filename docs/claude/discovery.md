# Discovery pipeline

Read before running discovery, interpreting or comparing its results, or changing discovery, fitness or the overfitting gates. Experiment history: [`../discovery-journal.md`](../discovery-journal.md).

## Current behaviour
- Discovery and screening share one code path (`NTScreeningRunner` → `StrategyCompiler`); a champion replays exactly within one run when `eval_windows=1`.
- **Liquidation is an opt-in overlay, OFF by default** (`liquidation_mode` `off|isolated|cross`, leverage in `(0,125]`; CLI `--liquidation-mode` / `--liquidation-leverage`, API `liquidation_mode` + `liquidation_leverage`, UI: a **Liquidation** Off/Isolated/Cross select plus a **Liquidation leverage** input shown only when the mode is on, promote/replay inherit the parent). It is **report-only**: with the mode on, fitness uses the liquidation-adjusted metrics (the same formula, recomputed from the truncated ledgers) with **no penalty and no gate**; the run records `notes.liquidation = {mode, leverage}` and champion/rejection/holdout rows carry `liquidation_count` / `liquidation_forfeited`. With the mode off no `liquidation*` key appears and the numbers are byte-identical.
- **Fail closed on liquidation data:** a missing or incomplete MARK 1m series, an unpriceable open survivor, or a fill/funding/cash flow at the run end fails the run with `LiquidationIntegrityError: liquidation_mode='isolated': ...` (never a `-999`/`-inf` row), at every stage (train, holdout, cross-window, WFA, full-range).
- **Parity limit (bead vibe-quant-vjno2):** screening overstates liquidation hits when a stop sits inside the liquidation distance — screening ends exposure at the strategy-bar close while validation's 1m stop fill is earlier. Strategy 239, BTCUSDT 4h, isolated 50x: screening 18 hits vs validation 0 (validation's exit precedes the screening hit ts in 18/18); at 125x both report 60. Discovery is report-only (fitness unaffected), but the reported screening count is an upper bound.
- **`path_divergence`:** a hit truncates the hit position's ledger, but NT's later positions are kept and re-sized as they were; their sizing used pre-liquidation equity and missed re-entries cannot be reconstructed, so the scan flags `path_divergence` (set when there is at least one hit). Every reported metric is recomputed from the truncated ledgers, not NT's raw path.
- **Peak RSS ≈ 1.15 GB per worker with the mode on** (measured on a mode-on run); mode off is unchanged.
- **Fitness** = 35% Sharpe + 25% (1 − MaxDD) + 20% PF + 20% Return; 0 below 50 trades.
- **`eval_windows` (default 3) stores WORST-of-N sub-window metrics** (min Sharpe/return/PF, max DD; each window needs ≥ max(1, min_trades // (2N)) trades). A full-window replay legitimately differs (`ReplayResponse.metrics_note` explains it).
- **Gates fail closed** (0 champions + `guardrail_rejections`); every run keeps a default 20% holdout used once as the final gate.
- **Bootstrap-CI floor** (statistic = t-stat mean/std·√n): 1m 0.5, 4h/1d 0.0 (1.0 is unpassable at ~50–180 trades/yr). Every champion forced past it with `no_bootstrap_ci=true` and then validated collapsed (Batch 41: 5.40 → −2.78; Batch 43 RAMS: 0.59 → −0.36); treat a flagged strategy as overfit.
- **DSR gate N is cumulative:** this run's evaluated strategies + prior non-mock discovery runs with the same timeframe and an overlapping train window (`notes.dsr_trials.gate_n/prior_n/prior_run_ids`). On a DB error it falls back to the run-only N and records `prior_error: true`. The gate and the worst-mode per-symbol PSR floor test the champion's **mark-to-market** daily series (the same series the buy-and-hold gate reads; see the 2026-10-12 comparability break), and a missing MTM series fails DSR closed.
- **Buy-and-hold gate (fail closed):** champions must beat the directional equal-weight, daily-rebalanced buy-and-hold Sharpe of their symbols over the train window, measured on the mark-to-market daily series (`notes.buy_hold_gate`); `symbol_agg=worst` also checks each symbol against its own benchmark. Skips only for a non-NT backtest fn; `--no-buy-hold-gate` disables.
- **Seed:** `--seed N` (CLI; auto-drawn otherwise, persisted in `notes.seed`) replays a run exactly with the same config and code.
- **Fails loudly:** an all-errored eval batch raises `DiscoveryEvaluationError` → run `failed`, not "0 champions".
- Validation's consistency check (`validation/consistency.py`) flags screening→validation collapse against the same window; holdout-validated champions are compared on their holdout metrics.
- **Compiler version hash** (`compiler_version_hash()`, stored in run notes for staleness) changes with indicator/codegen changes: `bd recall discovery:compiler-hash`. Champion rankings: `bd recall discovery:champions`.
- **1m is slow:** Rust-native indicators (SMA/EMA/CCI/STOCH/ATR) run ~10× faster than pandas-path ones (ADX/MACD/BBANDS/KAMA).

## Comparability breaks

Results from before each date are NOT comparable with later ones:
- **2026-10-13** (vibe-quant-2gyk1.1, job 20261012-p1-honest, liquidation T5b/T7): liquidation is an opt-in per-run overlay (`off|isolated|cross`). Opt-in only — a mode-off run is unchanged (import-isolated; exactness 239 IDENTICAL). A mode-on run is NOT comparable with a mode-off run. In **screening and discovery** the break has two causes: with the chosen leverage `L` the venue runs at `L` when the mode is on (mode off keeps its fixed 10x, `screening/nt_runner.py`), so NT's margin checks/rejections differ even at zero hits, and the liquidation scan itself truncates the ledgers. In **validation** the venue leverage is `parameters.leverage` in both modes (`validation/runner.py`), so only the liquidation itself changes. A mode-on run is also not comparable with another mode-on run at a different mode/leverage. Mode-on rows carry `liquidation_count` / `liquidation_forfeited` (NULL when off).
- **2026-10-12** (vibe-quant-68630, job 20261012-p1-honest): the overfitting pipeline's DSR (`python -m vibe_quant.overfitting`, discovery-champion recheck) and the screening pipeline's DSR filter test the mark-to-market daily statistics (`sweep_results.mtm_sharpe_daily/mtm_skewness/mtm_kurtosis/mtm_days`; the series T is `mtm_days`, so `--observations`/`num_observations` no longer affects DSR) instead of the realized NT Sharpe + stored moments, and re-apply the persisted worst-mode per-symbol PSR floor. A row without MTM statistics (every row written before this date, a discovery run whose DSR record predates the MTM switch) FAILS DSR closed; `passed_deflated_sharpe` flags and screening DSR survivor sets from before this date are not comparable (realized Sharpes overstate multi-day holds, ratio median 1.19). Headline `sharpe_ratio` columns are unchanged.
- **2026-10-12** (vibe-quant-y9ywf, job 20261012-p1-honest): discovery DSR (and the worst-mode per-symbol PSR floor and N_eff) test the mark-to-market daily series instead of the realized-balance series; DSR pass/fail and dsr records before this date are more lenient for multi-day holds and not comparable. Screening/validation metrics unchanged.
- **2026-10-11** (pandas-ta-classic 0.6.52 -> 0.8.32, job 20261011-grind): indicators computed through `compute_fn` change. ADX: first valid bar 13 -> 27 for period 14 (TA-Lib seeding of DI, rma(dx) seeded at the first valid dx), early values differ up to ~2 ADX points and converge to ~1e-14 later; RSI first valid bar +1 (the price diff has no bar 0, so the smoothing seed window now starts at bar 1) and ATR/SQUEEZE_RATIO first valid bar +1 (true range has no bar 0); WMA/ATR last-digit (1e-14) diffs; STOCH is index-aligned (full-length series, same tail values); KAMA/MACD/BBANDS/KC/Donchian/VWAP/MFI/CCI unchanged on the probe data. Strategy 239 (BTCUSDT 2024-01-01..2026-03-17 and 2024-H1) and strategy 67 (ADX+RSI, 4h, 2024-H1) metrics are bit-identical (thresholds/warmup luck); strategy 192 (ADX+STOCH, 1m, 2024-H1) moves sharpe -1.5593 -> -1.5300 and PF 0.7761 -> 0.7806. Treat any strategy using ADX/RSI/ATR/SQUEEZE_RATIO via compute_fn as not comparable across this date. The numpy ports (ADX, KAMA) were re-derived bit-identically against 0.8.32.
- **2026-10-10** (job 20261010-edge-engine): per-instrument fill release in screening, open-position marking, Binance instrument specs (BTC min notional 50), multi-symbol validation no longer fills at the signal close. Single-symbol validation unchanged.
